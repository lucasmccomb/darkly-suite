Chrome Web Store -- Privacy Practices Tab
------------------------------------------
Extension: Darkly for Google Sheets
Copy-paste ready for the CWS developer dashboard.


SINGLE PURPOSE DESCRIPTION
---------------------------
Darkly for Google Sheets applies a dark mode theme to Google Sheets with automatic
scheduling based on time of day, sunrise/sunset, or OS theme preference. A paid
subscription is required for all features.


PERMISSION JUSTIFICATIONS
--------------------------

storage:
Stores user preferences (dark mode on/off, schedule times, preserve grid colors setting)
and an anonymous device token for subscription verification using chrome.storage.sync so
settings persist across sessions and sync across the user's Chrome browsers. No personal
data is stored.

alarms:
Runs periodic checks for schedule-based and sunrise/sunset dark mode. An alarm fires
every minute to determine whether dark mode should be active based on the user's
configured schedule or local sunrise/sunset times. Also used for background polling
after checkout to detect when payment completes.

offscreen:
Creates an offscreen document to access the browser's Geolocation API, which is not
available in Manifest V3 service workers. Used only when the user opts into
sunrise/sunset scheduling. The offscreen document requests the user's approximate
location (with the browser's permission prompt) to calculate sunrise and sunset times.


HOST PERMISSION JUSTIFICATIONS
-------------------------------

https://docs.google.com/*:
Content scripts inject dark mode CSS and the settings panel UI into Google Sheets pages.
Content scripts match the narrower docs.google.com/spreadsheets/* pattern to apply
themes and render controls only on spreadsheet pages.

https://darklysuite.com/*:
Communicates with the Darkly payment API to check subscription status and initiate
checkout. An anonymous device token (randomly generated UUID) is sent to verify whether
the user has a paid subscription. Routine license checks transmit only this token. Starting a purchase or a purchase restore opens a Google sign-in page on darklysuite.com; the email address from that sign-in is stored server-side with the license record (see the personally identifiable information declaration). A lightweight
content script (landing-bridge.js) also runs on darklysuite.com to pass the extension's
anonymous device token to the checkout page via a CustomEvent, ensuring Stripe licenses
are linked to the correct extension instance.

sheetsdarkly.com + darklysuite.com (landing-bridge.js content script):
A small content script bridges communication between the landing/checkout pages and the
extension's background worker. It passes the extension's anonymous device token to the
page for checkout linking and forwards a checkout-complete signal back to the extension.
No page content is read or transmitted.

https://api.sunrise-sunset.org/*:
Fetches sunrise and sunset times for the user's approximate location when they opt into
sunrise/sunset scheduling. Only approximate latitude and longitude coordinates are sent, rounded to 1 decimal place (~11 km) before the request. This is a
public, free API with no authentication required.


DATA USE DECLARATIONS
----------------------

Personally identifiable information:  Collected (see details below)
Health information:                   Not collected
Financial and payment information:    Not collected
Authentication information:           Not collected
Personal communications:              Not collected
Location:                             Collected (see details below)
Web history:                          Not collected
User activity:                        Not collected
Website content:                      Not collected

Personally identifiable information details:
  - Collected during the purchase and restore-purchase flows only
  - Starting a purchase or restore opens darklysuite.com, where the user signs in
    with Google; the email address from that sign-in is stored server-side in the
    darklysuite.com license database, linked to the extension's anonymous device token
  - Use purpose: Functionality - verifying and restoring the user's license
  - Sold to third parties: No
  - The extension itself never reads the email address; routine license checks send
    only the anonymous device token

Location details:
  - Collected with user opt-in only (sunrise/sunset scheduling feature)
  - Use purpose: Functionality - calculating sunrise/sunset times
  - Sold to third parties: No
  - Transmitted outside the extension: Yes - approximate coordinates sent to the
    public sunrise-sunset.org API to retrieve sunrise/sunset times
  - Browser shows its own permission dialog before access is granted
  - Coordinates are rounded to 1 decimal place (~11 km) before transmission
  - Only the rounded coordinates are cached locally for up to 24 hours


REMOTE CODE
------------
Does this extension execute remote code? No
All code is bundled in the extension package. No remote scripts are loaded or executed.
